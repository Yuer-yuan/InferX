# 开源 PD 方案适配与验证设计

用户目标：morphx 和其他开源的先拿来适配解决当前 pd 问题，看能不能解决，解决得多好。

## 当前证据与目标

2026-10-14 实验发现 NInfer 单 GPU 长预填充期间跳过后到请求准入。D0/C4 控制短请求成功样本 P95 1.382 秒；加入 128K 冷请求后 P95 92.121 秒，62/120 个短请求 HTTP429。未修改引擎，因此尚未证明准入分支解释全部延迟。现有原始记录保留，不用论文倍数替代本机结果。

这次要实际构建、适配、运行 MorphX 和可部署的开源对照，测量同类工作负载下是否能消除阻塞、改善多少、代价是什么。成功可以是可量化的改善，也可以是充分验证的不适用或无改善结论；仅阅读源码、安装成功、小模型演示不能完成当前 27B 问题的验证。

## 方案与执行者选择

执行者选择顺序：原 NInfer 对照复测；llama.cpp 原生 continuous batching/chunking；可部署的现代 vLLM INT4/Marlin 路径；MorphX 编译器/runtime 适配。不同构建与模型容器隔离，固定来源提交及模型 revision/hash。

MorphX 必须验证真正生效：runtime 构建、至少一个带 _pk 变体的正确 kernel 实测、SM89 可用性，以及目标引擎 GPU kernel 路径覆盖。无补丁回退运行不能标为 MorphX 有效结果。它控制 kernel 资源而不直接改变请求准入；必要时将已有准入/分块机制与 MorphX 组合，并以同样的准入机制关闭 MorphX作消融，分离软件修复与 kernel 调度收益。若公开环境缺组件，实际尝试构建/移植并记录命令、日志和最小故障复现；不得以 README 依赖声明直接判失败。

llama.cpp 复用现有 Qwen3.8-27B-UD-Q4_K_M；vLLM 选择同源 Qwen3.8-27B 可在 SM89 上运行的 INT4 模型，而非以 3B 替代主实验。若混合 GDN 模型/量化/驱动约束阻止部署，保存实际失败证据，继续其他路径。对不同量化不宣称调度因果优势；同引擎开关消融优先。

## 工作负载与比较

- 复用 concurrency-roofline 已冻结的 24K 历史短工具调用、128K 冷长请求、128K 续接模板。保留完整 payload、SSE 和原生缓存证据。
- 核心对照：C4、MTP关闭、2.5 RPS 短控制；0.5 RPS 短 + 长冷；2.5 RPS 短 + 长冷；2.5 RPS 短 + 长续接。48 秒短请求波次，16 秒长请求到达，输出预算和请求到达表与原实验一致。
- 一个引擎必须实际完成 128K 长请求，不能以过小的 per-slot window、截断输入、拒绝长请求或只跑热短请求获得改善。共同主比较控制最大并发4与可容纳128K加其他短历史的容量；不同总预算/缓存精度/量化均报告。
- 主比较要求每组至少3个独立重复，采用独立服务重启或明确缓存重置后重新预热；不能把一次波次中的相关请求当独立实验。
- 基础组通过后测相应 MTP 档位；不支持 MTP 则明确标记。按显存启动约束调整探索组，不与容量匹配主组混合。
- 每个引擎通过 OpenAI 强制工具调用语义和非截断检查、完整代码验证，才进入性能比较。不同 tokenizer/chat template 的实际输入 token 数、实际 prefix hit/new token 数按引擎记录。无可观察缓存计数的结果不标成 verified resume。
- 固定 arrival 的所有尝试均计入：HTTP状态、错误、协议成功、工具有效率、完整延迟 P50/P95/P99、TTFT、5秒 SLO 有效 goodput、长请求完成与耗时、输出吞吐、峰值显存和排空时间。P99样本不足时缺失，不插值制造。
- 排空时间计入容量/吞吐分母，另报固定48秒窗口内完成数。reject 更多或长期延迟长请求不能当低尾延迟胜利。
