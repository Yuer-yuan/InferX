## Native memory, queues and clocks

The old block manager allocates the full input's blocks before prefill. Native `scheduler_reserve_full_isl=True` only checks capacity and allocates the current chunk. Faithful capacity accounting therefore requires a logical commitment view, not a dummy cache API or assuming the flag physically reserves memory.

Use the installed scheduler's `_request_remaining_blocks(request)` and underlying coordinator's full-sequence prediction for the actual hybrid groups. Effective free capacity is the actual native free pool minus the still-needed full-input commitments of already admitted requests. For a new admission, use the real prefix-hit block tuple and computed-token counts from the native waiting loop; do not replace them with an empty fake hit. Require candidate full need + other commitments + native watermark to fit before calling the unchanged native allocator. Per-step allocation protects other requests' commitments, excluding the current request's own. The native allocator remains the sole owner of blocks, CoW, checkpoint/replay and state copies.

Prove this view on the real native hybrid allocator: repeated queries do not mutate ownership; two individually fitting full prompts cannot be over-admitted jointly; admitted prefills complete without starvation and free their promises; shared prefixes/CoW, capacity release, abort, native paused queues and partial progress are preserved. The public policy can pause/reorder partial prefills while retaining their KV; this is not state-evicting preemption. Do not silently enable native decoder preemption as a fix. Allocation refusal must retain ownership and let eligible work advance; a wholly nonprogressing step fails qualification with evidence, not an efficacy score.

Keep all paused requests in native ownership and count every active/allocated request toward C4. Original policy view state is per real request ID and survives a paused/replayed request; remove it only when native ownership ends. Use native queue/state/output handling; introduce only ordering, eligibility, per-request token quotas and the full-input commitment boundary. No global replacement of the installed engine.

Native request arrivals use wall time; QoServe uses monotonic time. Bind one wall-to-monotonic offset at scheduler initialization and retain original arrival age for every request/resume. Record actual first model-token completion relative to arrival. The TBT deadline is the original max(actual prefill duration,TTFT budget)+successive-token budget, not a fresh deadline after every token.

Set native long-prefill cap0 for QoServe and all its paired controls: the author's dynamic search can choose2552, so cap2048 would silently clamp the policy. Native batched-token budget4096 accommodates this. Record requested and actually scheduled geometry; native hybrid alignment must not be treated as a fictitious1568 minimum chunk.

The dynamic total-token allowance is the native scheduling call's effective token budget, restored to its configured4096 ceiling after each call, including exceptions. This also feeds the native splitter's existing private-sub-block progress rule when a selected chunk is smaller than a state-cache block. It does not replace checkpoint or allocator code. The preliminary eligibility view can use actual pure native prefix/capacity queries, matching the author's `can_allocate` check before priority selection; final admission still uses the actual waiting loop's cache-hit tuple and unchanged native allocator. Genuine cached tokens inform the policy view's remaining input/context without advancing the native Request's computed-token counter.
