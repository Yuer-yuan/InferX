## 已发现并处理的问题

- 官方 CUDA redistrib 组件隔离安装时需要完整的 profiler 头文件和 `lib64 -> lib` 布局。缺少 profiler 头文件曾使 benchmark 翻译单元先包含系统旧 `driver_types.h`。包含路径跟踪定位后，补齐官方组件，原失败翻译单元语法检查通过。
- 提取 Ubuntu 开发包后，pkg-config 的绝对路径及 `.so` 链接需要指向正确位置。系统已有版本完全匹配的 runtime 包，隔离前缀中增加指向它们的链接，未更改系统库。
- NInfer 拒绝 `chat_template_kwargs.enable_thinking`。两个服务器启动配置已显式关闭 thinking，因此删除共享请求中冗余的 llama 专属字段，保留最初 HTTP400 原始记录，新增真实 HTTP 边界回归测试。
- 多轮追加提示探针最初复用了一个已被服务端关闭的 keep-alive 连接。主压测器已使用 `force_close=True`，探针也改为相同方式；四次完整请求重测通过。失败记录保留，不能计作模型答错。
- 质量汇总器曾把 HTTP400 当成空代码失败。回归测试观察到失败后，改为 `infrastructure_error`，74 项测试通过。
- NInfer draft8 在此环境启动时触发 `cudaErrorGraphExecUpdateFailure (update result 2)`。该点没有性能结果，不修改系统驱动来绕过它。

原始错误、修复前后日志均在远端 `tuning/`。编译、下载、配置探测和实际请求用于验证环境；指标计算和错误分类另有自动测试。最终测量及服务信息以主报告为准。

## 测量解释

NInfer 无 MTP、相同 greedy/seed 的重复请求也出现了注释措辞、代码组织和 token 数差异；已观察的六份独立代码输出均通过同一组执行测试。这意味着不能把所有逐字差异归因于 MTP，也不能宣称 greedy 严格确定。最终报告保留这一限制，不以少量代码测试替代完整质量 Benchmark。
