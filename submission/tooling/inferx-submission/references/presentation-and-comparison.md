# 展示与性能比较规范

本规范适用于 InferX 赛道A材料。用户指定的 Beamer 展示格式优先于 figurecraft 针对论文栏宽的默认值；图内语义、原生矢量与可读性检查继续适用。

## 最新用户要求：中英双版科研报告（2026-10-18）

用户明确否定原版版式，要求参照计算机视觉论文报告的规整表达，并交付中英文两份独立版本。本要求取代本文旧的Madrid、仅中文标题与禁止自定义主题条款：现在使用白底default画布、安静章节标签、短主张标题、统一位置与字号、大图和少量文字。八章语义和顺序保留，英文使用对应译名。`main.tex.in`是共享双语模板；输出`main.pdf`和同内容`InferX-ZH.pdf`，另输出`InferX-EN.pdf`，每份附独立可编译TeX。两版均须实际编译、逐页查看、登记各自PDF SHA，并运行两版check；中文版记录在latex-build.json/latex，英文在latex-build-en.json/latex-en。数据、公平比较、单轮范围与上游归属要求继续有效。本文后续保留的旧Madrid叙述仅适用于历史版本。

## 绘图与版式

使用 `$systems-paper-figurecraft`，按需读取其中的 contracts、editable-production、visual-system、figure-grammars、compact-layout 和 validation 参考文件。每张关键图先在 `submission/records/` 写明主张、证据路径、对象与箭头含义、目标尺寸和不应暗示的结论。机制示意的时间、宽度或数量若非实测，明确说明其示意性质。

原生 TikZ/PGFPlots 是本项目已有格式，保留可编辑标签、形状与连接线。图形契约从实验报告、源码和原始数据建立，不用生图模型重造实验曲线。无需为采用该 skill 改用 SVG 或栅格图。嵌入式 TikZ 源码与 Beamer PDF 可作为对应的可编辑源和矢量结果；独立导出图时交付图源与矢量PDF。PNG仅作内部检查或用户明确需要的输出。

显式使用 `\usetheme{Madrid}`，以此替代此前default主题要求。保留Madrid自带的标题栏、页脚、配色和字体层次，不再添加覆盖主题的标题模板、页脚模板或装饰性成果卡片；图内颜色仅表达稳定的技术语义。保留16:9、中文字体和必要的排版适配，不把文字缩小到难以投影阅读。规则的“约8页”是建议，保留八个章节的覆盖与顺序，不限定总页数，每章可多页；不添加无必要的封面、目录或章节过渡页。按5分钟项目汇报分配节奏，内容需要时直接拆页，无需仅因超过8页再次确认。

标题按下表章节原文填写，同一章节的连续多页使用相同标题，不加页序号、性能结论或宣传语；具体结论放在正文的一句简要说明中，再配图或少量要点。章节可用 `\section{...}` 与同名 frame 标题对应，不插入自动章节页。

更新模板时同步核对 `scripts/refresh.py` 的静态命令白名单及主题检查：只增加实际使用的合法命令，保留未知命令报错。主题必须为Madrid；使用可选的 `section` 或新增图像/代码命令前审查相应命令和资源依赖，不能关闭校验来通过检查。

| 章节顺序 | 章节标题（可连续多页） | 可选焦点范围（每页只选一个核心问题） |
|---|---|---|
| 1 | 项目概述 | 项目、队伍、目标任务和主要贡献 |
| 2 | 问题与目标 | 瓶颈证据、baseline表现和评测目标 |
| 3 | 整体方案 | 系统边界、原有基础与新增设计的位置 |
| 4 | 核心实现 | 关键设计决策、机制及实现工作量 |
| 5 | 结果与证据 | baseline/版本对照、SLO、质量及证据 |
| 6 | 工程化设计 | 版本、构建、量化缓存、回归与复现设计 |
| 7 | 成本、性能与取舍 | 容量与延迟边界、失败设计和代价 |
| 8 | 总结与不足 | 已被证据支持的成果与技术局限 |

## 每页一个重点与版式选择

排版前先在内部记录中列出各页的“所属章节、唯一问题、一句结论、版式、主图/主要证据、讲解时长”。章节是标题，唯一问题决定本页具体内容；不能将上表的整个范围照搬成一页的待讲清单。每页的文字、图表和数字必须共同解释这一个问题，重点用位置、留白和必要的强调突出。

控制单页信息量：只保留解释本页主张必需的短句和少量要点，避免长段、多个独立结论、并排无关图或完整实验清单。推导细节、完整参数/版本表和备选路线的展开移到技术文档或讲稿；支持比较公正性的关键条件不能删掉，可压成简短图注。内容过满时按同一章节拆为多页或删减无关信息，不能用小字、缩放整页或压缩行距补救。

按本页问题交替使用以下版式，不机械按固定五页循环，也不强迫每一类各占固定页数。连续讲述同一过程时，布局稳定优先于更换版式。

| 版式 | 结构与重点 |
|---|---|
| 图片页 | 上方零至两行说明，中间一张较大的图片或原生矢量图，下方可加简短图注。图承担主要解释任务，不另铺一组独立要点。 |
| 概念页 | 简短定义，配合居中的公式、箭头或对应关系图。只定义理解当前问题必需的概念和符号。 |
| 对比页 | 左右两栏或紧凑表格，围绕同一个比较问题；相同维度对齐，清楚标识baseline、候选、条件及取舍。 |
| 过程页 | 分步骤展示输入、处理过程和输出；箭头表示真实依赖或转换，强调本页需要解释的步骤。 |
| 实践页 | 依次展示代码、流程图、真实运行截图和结果，全部对应同一项实践问题。避免贴完整代码或满屏日志，截取能证明当前步骤的片段。 |

实践链按“代码→流程图→运行截图→结果”排序，可分布在同一章节的连续多页中，也可用紧凑的有序片段支持本页的同一结论；不为凑齐载体把四份完整材料挤在一页。未拿到的运行截图不能用模型或排版模拟成真实运行证据，缺项写入验收记录。需要分步展示时优先用有明确主旨的连续frame；若用overlay或自动续页，应核对实际PDF的每个输出页，避免空白、重复或阅读跳动，不能只检查frame数量。

## 图片比例、留白与连续页

图片通常占正文区域的大部分空间，说明文字围绕图组织。布局以Madrid标题栏与页脚之间的实际可用区域计算，先预留短图注、必要脚注及安全间距，再确定主图最大宽高；不能沿用旧主题的正文高度而让图片压住页脚。

图片按原始比例缩放，同时约束宽度和可用高度；外部图片使用 `keepaspectratio`，不独立拉伸宽高，也不裁掉关键标签来迁就版面。TikZ/PGFPlots从源布局保证文字清晰，缩图前先减少无关内容、修复内部留白和连接线，不能把图中文字整体缩到难以阅读。截图是真实栅格证据，与架构/机制图的原生矢量要求区分，引用时保留来源。

同一过程跨页时固定主图的锚点、显示尺寸、文字区域、图注基线和颜色/符号；用局部高亮或增量标注强调当前步骤。对同一张图复用同一边界和缩放，不因显示内容变化自动重新裁切，造成前后跳动。页数随解释需要安排，不用重复页或空白页凑数。

## 问题→设计选择→效果

先为每个要展示的关键优化建立一行内部记录：

| 优化点 | 问题及定位证据 | 设计选择与理由 | 备选/旧方案 | 效果及对照条件 | 代价/局限 | 来源 |
|---|---|---|---|---|---|---|

据此选图：瓶颈用资源竞争/时间线，机制用计算路径或状态变化，收益用同条件数据图。跨页保持同一优化的名称、版本和图形语义，使观众能对应问题、设计和效果；不强制每页重复三个相同卡片。

“选择 INT4”“调整并发”仅是动作，还需解释为什么在该热点/约束下选择它、保留了什么、付出什么。收益没有有效对照时只报告实测结果，不能把机理推测写成已证明的因果。无收益或退步的设计保留实际结果及未被采用的理由。

工作量用可核验的覆盖范围、算子/路由数量、校准与验证范围和实验迭代展示；ledger行数仍称实验/检查记录。保持上游贡献与本组新增工作边界。

## baseline 与历史版本

1. 搜索现有官方/原始基线、未经该项优化的版本和此前优化版本。记录找到哪些、为何选它们及证据路径；没有同条件 baseline 时如实说明当前对照范围，将补测需求放入验收记录，不能伪造或自动启动GPU补跑。
2. 比较前检查：硬件/单卡数/功耗、模型与权重/精度、source与binary/cache身份、服务与MTP等配置、ISL/OSL及上下文、并发与实际活跃批量、请求payload/顺序/种子、warmup/样本量/重复轮次、计时范围/吞吐分母/P95算法、错误及截断。设计变量本身可以不同，其他差异必须交代；若有多个变化，不归因于单项设计。
3. **受控对照**：除设计变量外条件匹配，才计算该条件下的增益；注明基准值、候选值、单位、样本及轮次。吞吐增幅为 `(候选−基准)/基准`，延迟降幅为 `(基准−候选)/基准`。单轮结果不伪造误差条或稳定性结论。
4. **历史版本展示**：可展示优化过程，但分组标明协议、版本和条件差异；条件不匹配时用独立面板/表格，不连成暗示受控实验的增益曲线，不算统一加速倍数。旧ZIP100+8与扩展128+8必须分开；C不同的点可用于同一版本容量曲线，不能解释为某优化的净收益。
5. 对照范围应服务于具体设计问题。不要只挑最弱基线或仅展示候选有利指标；在整套材料中完整报告TTFT、TPOT、吞吐、SLO及必要的质量/资源代价，指标按同条件对应。单页只突出当前问题所需的指标及会改变结论的取舍，其余完整值保留在技术文档，不把所有指标硬塞进每一页。失败、取消、空final和截断依原统计范围保留，未完成运行不能当完成结果。
6. 性能与质量各自绑定版本。当前性能9270与质量40b3不能拼成同版本联合达标；旧采样/greedy与新thinking质量也不能直接作纯质量提升。固定数字只从本次审阅后的registry取值，以上短身份仅是已知混淆示例，不指定未来主版本。

图中明确 baseline 和版本身份、坐标轴/单位、统计口径、条件与SLO阈值。柱状图从零起；必要的局部坐标范围要明显标注，避免视觉夸大。原始成绩可保留与研究结论相关的精度，图上显示取便于阅读的有效位数；判定SLO使用原始精度。

## 本轮材料执行后的验收

将以下实际结论写入验收记录，缺项不能填成通过：

- 读取并应用的 figurecraft 资料；每张图的主张、证据与箭头/边界核验结论。
- Madrid主题、八个章节的原文标题及顺序、每页一个问题和一句主旨；允许章节连续多页，模板与生成TeX均核对。
- 图片/概念/对比/过程/实践版式按内容合理交替；简短正文、重点醒目，不以小字或密集图表掩盖内容过量。
- 图片比例正确、主图占据主要正文空间，图注/脚注/页脚互不覆盖；连续页的图片位置、显示尺寸和文字布局稳定。
- 关键优化的问题、设计理由、效果与取舍能对应，工作量不冒充性能收益。
- 找到的baseline及历史版本、对照类型与条件差异、增益计算范围、负面结果保留情况。
- TeX独立编译、实际PDF页数与预览/视觉登记一致、字体与矢量内容、全部页面在投影尺寸下的可读性和跨图一致性；检查项目汇报节奏可控制在5分钟。若走SVG/PDF路径，运行figurecraft的结构审计，仍需人工核验语义与画面。

继续使用主skill的编译、渲染、视觉验收SHA绑定和check流程。check核对显式Madrid及章节标题：压缩连续同名标题后应与八个章节顺序一致，无固定frame数或PDF页数限制。内容密度、主题聚焦、版式合理性、图片比例、汇报节奏和实验因果需实际审阅，不因脚本退出码为0而自动通过。
